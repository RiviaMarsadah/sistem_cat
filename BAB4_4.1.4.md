# 4.1.4 Implementasi Tampilan Mobile App (Flutter)

Bagian ini menjelaskan tampilan antarmuka pengguna (user interface/UI) pada aplikasi mobile CAT yang dibangun menggunakan Flutter. Aplikasi mobile dirancang khusus untuk siswa sebagai pengguna utama yang mengerjakan ujian melalui perangkat seluler. Seluruh halaman disertai placeholder gambar serta penjelasan singkat mengenai komponen dan fungsinya.

---

## 4.1.4.1 Struktur Direktori Flutter

`[][Gambar 4.x Struktur Direktori Flutter Mobile App]`

Menampilkan gambar berupa hierarki folder dan file pada direktori proyek Flutter. Struktur direktori aplikasi mobile CAT secara garis besar terdiri atas beberapa direktori utama, yaitu folder `lib/` sebagai direktori kerja utama yang menyimpan seluruh kode sumber Dart. Di dalam `lib/` terdapat folder `core/` yang memuat tiga buah layanan inti (core services), yaitu file `api_client.dart` yang berisi konfigurasi client untuk melakukan request HTTP ke backend menggunakan package `http`, termasuk pengelolaan header Authorization Bearer JWT, base URL yang dapat dikonfigurasi, dan response parser; file `auth_service.dart` yang menangani seluruh alur autentikasi menggunakan Google Sign-In OAuth 2.0, penyimpanan token JWT serta data profil siswa ke SharedPreferences, dan verifikasi token ke endpoint backend; serta file `settings_service.dart` yang mengelola konfigurasi aplikasi seperti URL server backend yang dapat diubah oleh siswa sesuai jaringan yang digunakan. Folder `screens/` yang berada di dalam `lib/` merupakan direktori yang menyimpan seluruh halaman (screen) aplikasi Flutter. Setiap file screen di dalamnya menggunakan pola StatefulWidget agar dapat mengelola state lokal seperti timer ujian, jawaban siswa, dan navigasi antar tab. Folder `assets/` pada tingkat root proyek menyimpan file gambar seperti logo aplikasi dan logo Google yang digunakan pada halaman login. File `pubspec.yaml` sebagai file konfigurasi dependency Flutter juga berada di tingkat root, yang mendefinisikan package-package yang digunakan seperti `google_sign_in`, `shared_preferences`, `http`, dan `kiosk_mode`. Dengan adanya pemisahan folder seperti ini, struktur kode aplikasi mobile menjadi lebih terorganisir dan mudah dipelihara.

## 4.1.4.2 Halaman Login (LoginPage)

`[][Gambar 4.x Halaman Login Mobile App]`

Berfungsi sebagai halaman awal (entry point) aplikasi mobile CAT yang digunakan oleh siswa untuk melakukan autentikasi sebelum mengakses fitur-fitur ujian. Desain halaman login menggunakan tema warna biru tua (navy) sebagai latar belakang yang mencakup seluruh layar, dipadukan dengan elemen dekoratif transparan berupa lingkaran besar di pojok kanan atas dan efek gradien radial. Pada bagian tengah halaman, terdapat sebuah kartu login transparan yang berisi logo aplikasi \"ATEKA Dashboard\" dengan nama lengkap \"Computer Assisted Test\", serta teks \"Selamat Datang\" yang menyambut pengguna. Di bawah header tersebut terdapat tombol \"Masuk dengan Google\" yang menggunakan custom painted icon Google berwarna (biru, hijau, kuning, merah) serta teks tombol yang berubah menjadi \"Memproses...\" saat proses login sedang berlangsung. Halaman ini juga menyediakan tombol settings berupa ikon gear di pojok kanan atas yang ketika diklik akan membuka halaman pengaturan URL server backend. Proses autentikasi dilakukan melalui Google Sign-In OAuth 2.0, di mana aplikasi meneruskan Google ID Token ke endpoint backend `/api/auth/google` untuk diverifikasi dan ditukar dengan JWT token. Jika login berhasil dan role pengguna adalah \"siswa\", sistem akan menyimpan token JWT dan data profil ke SharedPreferences, lalu mengarahkan pengguna ke halaman dashboard. Jika login gagal, sistem akan menampilkan AlertDialog yang berisi pesan kesalahan yang spesifik, seperti \"Akun tidak terdaftar sebagai siswa\" atau \"Tidak dapat terhubung ke server\". Desain halaman ini menggunakan pendekatan Material Design dengan transparansi dan gradasi warna yang modern, serta sepenuhnya responsif terhadap berbagai ukuran layar perangkat Android.

## 4.1.4.3 Halaman Dashboard — Tab Beranda (DashboardScreen)

`[][Gambar 4.x Halaman Dashboard Tab Beranda]`

Menampilkan tampakan tab pertama dari halaman dashboard aplikasi mobile yang berfungsi sebagai layar utama siswa setelah berhasil login. Tab Beranda memiliki header gradient berwarna biru tua yang mencakup seluruh lebar layar, dengan border radius besar di bagian bawah yang memberikan kesan modern dan premium. Header ini memuat dua buah statistik di bagian dalam, yaitu jumlah \"Ujian Selesai\" dan \"Rata-rata Skor\" yang diambil secara dinamis dari API backend. Pada bagian bawah header, terdapat sapaan \"Selamat Datang, [Nama Siswa]\" yang diambil dari data profil Google yang sudah disimpan, beserta avatar foto profil siswa yang diambil dari Google Foto jika tersedia, atau ikon orang default jika foto tidak ada. Jika terdapat ujian yang sedang aktif (status \"berlangsung\" atau \"waiting\"), sistem akan menampilkan kartu \"Ujian Aktif\" berwarna biru muda yang dilengkapi tombol \"Lanjutkan\" untuk langsung masuk ke sesi ujian yang sedang berjalan. Jika tidak ada ujian aktif, sistem akan menampilkan kartu banner \"Siap Ujian?\" yang mendorong siswa untuk memasukkan token check-in. Di bagian bawah header, terdapat daftar \"Ujian Hari Ini\" yang memuat seluruh jadwal ujian yang dijadwalkan untuk hari ini berdasarkan data dari API, di mana setiap item daftar menampilkan nama ujian, mata pelajaran, serta status ujian berupa badge berwarna (hijau untuk \"Selesai\", oranye untuk \"Berlangsung\", biru untuk \"Belum Mulai\"). Siswa dapat mengetuk item daftar untuk membuka dialog input token check-in 6 digit sebelum memulai ujian. Tab Beranda juga menyediakan mekanisme pull-to-refresh untuk memperbarui data ujian aktif dan daftar ujian hari ini secara langsung dari server. Seluruh data pada tab ini dimuat secara asinkron menggunakan Future API Flutter, sehingga UI tetap responsif selama proses pengambilan data berlangsung.

## 4.1.4.4 Halaman Dashboard — Tab Riwayat (DashboardScreen)

`[][Gambar 4.x Halaman Dashboard Tab Riwayat]`

Berfungsi sebagai tampakan tab kedua dari halaman dashboard yang menampilkan daftar riwayat ujian yang telah dikerjakan oleh siswa. Tab Riwayat dilengkapi dengan header bertuliskan \"Riwayat Ujian\" disertai ikon dan subtitle \"Pantau perkembangan dan hasil ujian Anda.\" Daftar riwayat dimuat secara asinkron dari endpoint API `/api/siswa/ujian/riwayat` menggunakan widget FutureBuilder, dan setiap item riwayat ditampilkan dalam bentuk kartu (Card) yang dapat diketuk untuk membuka halaman hasil ujian. Setiap kartu riwayat memuat badge skor berbentuk persegi panjang berwarna kuning/oranye yang menampilkan nilai akhir ujian dalam angka besar, nama paket ujian yang diwarnai biru tua, serta tanggal pengerjaan ujian dalam format ringkas. Kartu-kartu ini memiliki efek bayangan (box shadow) dan border radius yang memberikan kesan bersih dan modern. Jika koneksi terputus atau data gagal dimuat, sistem akan menampilkan state kosong \"Belum ada riwayat ujian\" yang disertai tombol \"Coba Lagi\" untuk melakukan pengambilan ulang data. Siswa dapat menggeser daftar ke bawah untuk melakukan refresh data menggunakan widget RefreshIndicator bawaan Flutter. Ketika siswa mengetuk salah satu kartu riwayat, sistem akan membuka ExamResultScreen dengan membawa parameter ujianSiswaId yang diperlukan untuk mengambil data hasil ujian secara detail dari API.

## 4.1.4.5 Halaman Dashboard — Tab Akun (DashboardScreen)

`[][Gambar 4.x Halaman Dashboard Tab Akun]`

Merupakan tampakan tab ketiga dari halaman dashboard yang menyajikan informasi akun dan profil siswa yang sedang login. Tab Akun menggunakan layout ListView yang memuat beberapa kelompok informasi yang dibedakan berdasarkan kategori. Kelompok pertama adalah \"Informasi Akademik\" yang berisi kartu profil utama atas dengan nama siswa dan label \"Siswa ATEKA\", kartu NIS, kartu Kelas, dan kartu Program Studi yang masing-masing diambil secara dinamis dari SharedPreferences menggunakan widget FutureBuilder. Kartu-kartu informasi ini menggunakan desain ListTile dengan ikon berwarna biru tua pada sebelah kiri dan teks judul tebal di atas teks subtitle yang lebih kecil. Kelompok kedua adalah \"Pengaturan & Sesi\" yang memuat dua buah kartu aksi, yaitu kartu \"Server\" yang menampilkan URL server backend saat ini dan berfungsi sebagai shortcut menuju halaman pengaturan untuk mengubah IP server, serta kartu \"Keluar\" yang berwarna merah dan berfungsi untuk logout dari aplikasi. Proses logout menampilkan dialog konfirmasi \"Yakin ingin keluar dari akun?\" dengan dua tombol, yaitu \"Batal\" dan \"Keluar\". Jika dikonfirmasi, sistem akan memanggil fungsi logout dari AuthService yang menghapus seluruh data token dan profil dari SharedPreferences, serta melakukan Google Sign-Out, lalu mengarahkan pengguna kembali ke halaman Login. Seluruh kartu pada tab Akun menggunakan desain Material Card dengan border radius, border warna biru muda, dan bayangan halus agar konsisten dengan tema visual aplikasi.

## 4.1.4.6 Halaman Pengambilan Ujian — Tampilan Soal (ExamAttemptScreen)

`[][Gambar 4.x Halaman Pengerjaan Soal Tipe Pilihan Ganda]`

`[][Gambar 4.x Halaman Pengerjaan Soal Tipe Pilihan Ganda Kompleks]`

`[][Gambar 4.x Halaman Pengerjaan Soal Tipe Pilihan Ganda Kategori Benar/Salah]`

Berfungsi sebagai tampakan halaman utama pengerjaan soal ujian yang menampilkan pertanyaan dan opsi jawaban sesuai dengan tipe soal yang sedang aktif. Halaman ini memiliki tiga tipe tampilan yang berbeda berdasarkan kategori soal dari database. Untuk tipe soal \"Pilihan Ganda Sederhana\" (simple), setiap opsi jawaban ditampilkan dalam widget RadioListTile yang hanya mengizinkan satu pilihan tunggal, dengan highlight biru pada opsi yang sedang dipilih. Untuk tipe soal \"Pilihan Ganda Kompleks\" (complex), setiap opsi jawaban ditampilkan dalam widget CheckboxListTile yang memungkinkan siswa memilih lebih dari satu opsi sekaligus sebagai jawaban benar, ditandai dengan centang biru pada setiap opsi yang dipilih. Untuk tipe soal \"Pilihan Ganda Kategori Benar/Salah\" (category), halaman menampilkan sebuah tabel interaktif dengan kolom \"Pertanyaan\" (kolom A–F berisi pernyataan), kolom \"Benar\", dan kolom \"Salah\", di mana siswa dapat mengetuk ikon centang atau ikon silang pada setiap baris untuk menandai pernyataan sebagai Benar atau Salah. Pada bagian atas halaman pengerjaan soal, terdapat chip informasi yang terdiri dari tiga komponen, yaitu chip progress \"Soal N/N\" yang menunjukkan posisi soal saat ini, chip tipe soal yang bewarna berbeda-beda untuk setiap kategori (hijau untuk sederhana, oranye untuk kompleks, merah untuk kategori), serta chip timer countdown yang menampilkan sisa waktu ujian dalam format jam:menit:detik. Bagian tengah halaman menampilkan kotak berisi nomor soal diikuti teks pertanyaan yang diambil dari data API, dan jika soal memiliki gambar pendukung, gambar akan dimuat menggunakan widget Image.network dengan placeholder loading dan error handling. Navigation bar di bagian bawah layar berisi tiga tombol, yaitu tombol \"Sebelumnya\" untuk kembali ke soal sebelumnya, tombol \"Ragu-Ragu\" untuk menandai soal yang belum pasti jawabannya, dan tombol \"Lanjut\" atau \"Selesai\" untuk melanjutkan ke soal berikutnya atau menyelesaikan ujian. Jika opsi keamanan Kiosk Mode diaktifkan pada jadwal ujian, halaman ini juga mengaktifkan Screen Pinning melalui package `kiosk_mode` agar siswa tidak dapat keluar dari aplikasi selama ujian berlangsung.

## 4.1.4.7 Halaman Pengambilan Ujian — Navigasi Soal (ExamAttemptScreen)

`[][Gambar 4.x Navigasi Soal dengan Grid Warna]`

Menyajikan tampakan komponen navigasi soal yang berada di bawah area pertanyaan dan opsi jawaban. Komponen ini berupa container berkotak dengan header bertuliskan \"Navigasi soal\" yang diikuti oleh grid berisi tombol-tombol angka bulat kecil yang disusun dalam 10 kolom. Setiap tombol angka pada grid memiliki warna latar yang berbeda-beda sesuai dengan status jawaban siswa pada soal nomor tersebut, yaitu hijau untuk \"Dijawab\", kuning/oranye untuk \"Ragu-Ragu\", dan putih untuk \"Kosong\". Tombol angka yang sedang aktif dilihat dari nomor soal yang sedang ditampilkan memiliki border biru yang lebih tebal dari tombol lainnya, sehingga siswa dapat dengan mudah mengetahui posisi soal yang sedang dikerjakan. Di bagian bawah grid navigasi, terdapat tiga legend pill horizontal yang masing-masing menampilkan label \"Dijawab\", \"Kosong\", dan \"Ragu-Ragu\" disertai jumlah soal yang masuk dalam setiap kategori, sehingga siswa dapat memantau secara sekilas cuántos soal sudah dijawab, belum dijawab, atau ditandai ragu-ragu. Siswa dapat mengetuk tombol angka mana saja pada grid untuk langsung melompat ke nomor soal yang diinginkan tanpa harus menekan tombol Sebelumnya atau Lanjut berulang kali. Perlu diperhatikan bahwa tombol angka untuk soal di luar rentang efektif (jumlah soal yang sebenarnya ada dalam paket) akan ditampilkan dengan opacity lebih rendah (0.55) dan tidak bisa diklik, untuk menghindari navigasi ke nomor soal yang tidak valid. Desain grid navigasi ini mengadopsi pola yang umum digunakan pada aplikasi ujian berbasis komputer, yaitu Quick Navigation Panel yang memungkinkan siswa melihat gambaran keseluruhan progreso ujian secara sekilas.

## 4.1.4.8 Halaman Pengambilan Ujian — Timer & Submit (ExamAttemptScreen)

`[][Gambar 4.x Dialog Input Token Checkout 6 Digit]`

`[][Gambar 4.x Dialog Konfirmasi Submit Ujian]`

`[][Gambar 4.x Dialog Peringatan Waktu Habis]`

Berfungsi sebagai tampakan mekanisme timer countdown dan proses submit ujian pada halaman pengerjaan soal. Timer countdown berjalan secara real-time menggunakan Timer.periodic dengan interval 1 detik, menghitung mundur dari selisih antara waktu mulai ujian ditambah durasi atau waktu selesai jadwal. Timer ditampilkan pada chip di bagian atas halaman yang berwarna biru secara default dan berubah menjadi merah ketika sisa waktu kurang dari 5 menit (300 detik), untuk memberikan peringatan visual kepada siswa bahwa waktu hampir habis. Ketika timer mencapai angka nol, sistem secara otomatis menampilkan dialog peringatan \"Waktu Habis!\" dan setelah jeda 3 detik akan langsung melakukan auto-submit tanpa memerlukan input token checkout dari siswa, menggunakan flag `isTimeUp: true` yang dikirim ke backend. Untuk submit manual sebelum waktu habis, sistem menampilkan dialog input token checkout 6 digit sebelum jawaban dikirim ke server. Dialog ini berupa AlertDialog yang berisi TextField berkaratakter besar, where siswa harus memasukkan 6 karakter token checkout yang diberikan oleh pengawas ujian. Tombol \"Kirim (Selesai)\" pada dialog hanya aktif ketika tepat 6 karakter sudah dimasukkan, dan siswa dapat membatalkan submit dengan tombol \"Batal\". Jika terdapat soal yang belum dijawab (status \"Kosong\"), sistem akan menampilkan dialog peringatan \"Ujian Belum Lengkap\" yang menyebutkan jumlah soal yang belum diisi, dan mencegah siswa melanjutkan submit sampai seluruh soal dijawab atau ditandai ragu-ragu. Perlu dicatat bahwa soal yang ditandai \"Ragu-Ragu\" tidak menghalangi proses submit, karena siswa sudah memberikan tanda bahwa soal tersebut belum pasti dijawab. Sebelum submit答案, sistem juga menjalankan mekanisme Smart Sync yang secara otomatis menyimpan jawaban setiap soal ke backend setiap kali terjadi perubahan dengan jeda waktu debounce 800 milidetik menggunakan Timer, sehingga jawaban siswa tidak hilang meskipun koneksi terputus atau aplikasi ditutup secara tidak sengaja.

## 4.1.4.9 Halaman Hasil Ujian — Tab Rekap Hasil (ExamResultScreen)

`[][Gambar 4.x Tab Rekap Hasil Ujian]`

`[][Gambar 4.x Progress Bar dan Informasi Durasi Pengerjaan]`

Merupakan tampakan tab pertama dari halaman hasil ujian yang menampilkan rangkuman performa siswa dalam mengerjakan ujian. Halaman ini diakses oleh siswa setelah menekan tombol submit dan menerima konfirmasi dari backend bahwa ujian telah selesai. Tab Rekap Hasil menggunakan layout ListView yang scrollable dan memuat beberapa komponen utama. Komponen pertama adalah header nama paket ujian dan mata pelajaran yang diwarnai biru tua. Komponen kedua adalah kotak besar yang menampilkan nilai akhir ujian dalam angka besar 56pt yang berwarna berbeda-beda sesuai dengan ketentuan kelulusan, yaitu hijau untuk nilai >= 75, oranye untuk nilai >= 50, dan merah untuk nilai di bawah 50. Di bawah angka nilai, terdapat progress bar horizontal yang menampilkan proporsi nilai terhadap skala 100, serta label \"Nilai Akhir\" sebagai keterangan. Komponen ketiga adalah grid 2x2 yang memuat empat kartu statistik ringkas berisi \"Total Soal\", \"Dijawab\", \"Ragu-Ragu\", dan \"Kosong\", masing-masing dengan warna dan angka yang berbeda untuk memudahkan siswa membaca distribusi jawaban secara cepat. Komponen keempat adalah kotak informasi \"Waktu Pengerjaan\" yang menampilkan waktu mulai, waktu selesai, dan durasi pengerjaan ujian dalam format jam:menit:detik. Seluruh data pada tab ini diambil dari endpoint API `/api/siswa/ujian/[ujianSiswaId]/hasil` yang mengembalikan objek JSON berisi data rekapitulasi dan detail soal-soal yang sudah dikerjakan. Loading state ditampilkan menggunakan CircularProgressIndicator центрированная белым цветом, sementara jika terjadi kesalahan koneksi, sistem menampilkan tampilan error dengan pesan spesifik dan tombol \"Coba Lagi\" untuk pengambilan ulang data.

## 4.1.4.10 Halaman Hasil Ujian — Tab Review Jawaban (ExamResultScreen)

`[][Gambar 4.x Tab Review Jawaban dengan Expandable Card]`

Berupa tampakan tab kedua dari halaman hasil ujian yang memungkinkan siswa untuk melakukan review terhadap jawaban yang sudah diberikan pada setiap nomor soal. Tab Review Jawaban menggunakan layout ListView.separated yang memuat kartu-kartu expandable untuk setiap soal secara berurutan. Setiap kartu soal pada kondisi awal (collapsed) hanya menampilkan nomor soal dalam kotak bulat biru, teks preview pertanyaan dibatasi maksimal 2 baris dengan ellipsis, badge status jawaban (Dijawab/Ragu-Ragu/Tidak Dijawab) dengan ikon dan warna yang berbeda, serta badge tipe soal (Pilgan/Kompleks/Kategori). Ketika siswa mengetuk kartu soal, kartu akan melakukan expand untuk menampilkan detail lengkap yang mencakup: gambar soal (jika ada), daftar seluruh opsi jawaban yang masing-masing disertai label huruf A hingga F, container jawaban siswa yang diwarnai sesuai status (biru untuk dijawab, oranye untuk ragu-ragu, abu-abu untuk kosong), serta jawaban siswa yang diformat ulang agar mudah dibaca. Format display jawaban bervariasi sesuai tipe soal: untuk tipe sederhana dan kompleks, jawaban ditampilkan sebagai daftar opsi yang dipilih (misalnya \"A. Ayam\", \"C. Cacing\"); untuk tipe kategori, jawaban ditampilkan apa adanya seperti \"B,S,B\". Kartu review soal menggunakan Material InkWell untuk efek ripple saat diketuk, serta animasi expand/collapse yang halus. Tab Review Jawaban ini berfungsi sebagai alat belajar mandiri bagi siswa, karena memungkinkan mereka melihat letak kesalahan tanpa harus langsung berkomunikasi dengan guru. Jika detail jawaban tidak tersedia dari server, tab akan menampilkan pesan \"Detail jawaban tidak tersedia\" secara centered.

## 4.1.4.11 Halaman Pengaturan (SettingsScreen)

`[][Gambar 4.x Halaman Pengaturan Server Backend]`

Berfungsi sebagai tampakan halaman pengaturan yang memungkinkan siswa untuk mengonfigurasi alamat URL server backend sesuai dengan jaringan yang digunakan. Halaman ini menggunakan tema warna biru tua (navy) yang sama dengan halaman login untuk menjaga konsistensi visual aplikasi. Pada bagian atas halaman terdapat header \"Pengaturan Server\" disertai tombol kembali berarah kiri yang berfungsi untuk kembali ke halaman sebelumnya. Di bagian tengah halaman terdapat TextField yang sudah terisi dengan URL server backend saat ini yang diambil dari SettingsService, dengan hint text placeholder \"http://192.168.1.43:3000\" yang memberikan contoh format IP yang diharapkan. Di bawah TextField, terdapat teks bantuan berwarna putih transparan yang berbunyi \"Ubah sesuai IP komputer yang menjalankan backend saat HP dan laptop dalam satu jaringan\", yang memberi tahu siswa mengenai syarat konfigurasi URL yang benar. Tombol \"Simpan\" berwarna biru cerah terletak di bagian bawah halaman, dan ketika ditekan akan menjalankan validasi URL yang memastikan URL tidak kosong dan dimulai dengan \"http://\" atau \"https://\". Jika validasi berhasil, sistem akan memanggil fungsi `setBaseUrl` dari SettingsService untuk menyimpan URL baru ke SharedPreferences secara permanen, menampilkan SnackBar konfirmasi \"URL server disimpan\", lalu menutup halaman pengaturan dan kembali ke halaman sebelumnya. Jika validasi gagal, SnackBar berwarna merah akan menampilkan pesan kesalahan yang spesifik. Halaman ini menjadi sangat penting dalam konteks penggunaan aplikasi mobile di sekolah, karena siswa mungkin perlu mengubah URL server ketika menggunakan jaringan sekolah yang berbeda dari jaringan rumah atau saat ujian berlangsung di laboratorium komputer yang berbeda.
